# TV smoothness pass (SmartTube lessons) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make the TV app (Android TV, Fire TV Stick with 1 GB RAM) feel as fast and clean as SmartTube: do almost nothing per focus move, mount only visible tiles, cut needless animation.

**Architecture:** Same React Native screens. Move per-focus work off React state and out of the focus path; virtualize Home; replace layout animations with transforms or instant changes on TV. Phones keep their look; they get the shared savings (focus cost, player re-renders).

**Tech Stack:** Expo SDK 58, react-native-tvos 0.88 (Fabric), Reanimated 4, FlashList, Zustand, Jest.

**Spec:** the approved comparison in chat on 2026-11-08 (SmartTube vs Zoggyfin). Maintainer decisions: do all six recommendations; keep the TV billboard but update it only after focus rests on a tile for about 500 ms.

## Global Constraints

- Every platform keeps working (AGENTS.md "every feature works on every platform"). Changes to look and motion apply when `isTV` (from `src/platform/tv.ts`) unless a task says otherwise.
- Design system only: tokens from `@/theme` (`useTheme`, `motion`, `tv`, `sizes`); no raw colours or sizes. If a new token is needed, add it to `docs/design/theme.ts` first, then copy to `src/theme/theme.ts`.
- No new dependency. No new native module API that JS needs (old binaries get the JS by OTA).
- D-pad focus must never trap; Back always goes back; focus memory per row must survive (return to a row lands on the tile you left).
- `pnpm typecheck`, `pnpm lint`, and `pnpm test` pass. Add or update tests for pure logic you add.
- Commit identity `zog-tech`; message style from AGENTS.md section 7; end each commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Holding Right on a 20-tile row on TV: focus reaches the end, the row scrolls, nothing drops or jumps back.
2. Leaving a row and coming back (Up then Down): focus returns to the tile you left, also after that tile scrolled out of the mounted window.
3. Moving fast across tiles: the billboard does not change until focus rests ~500 ms; no network fetch per passed tile.
4. Side menu: open and close with Left/Right/Back; focus returns to the content (known old bug: Right from the open menu may not return focus — do not make it worse).
5. Player on phones and TV: the seek bar and times still update; controls still show on any key and hide on time.

### Task 1: Nothing extra on focus

**Files:** `src/components/touchable.tsx`, `src/features/tv/billboard.tsx`, the TV tile and shelf code (`src/features/tv/shelf.tsx` and the row/tile components it renders, for example `src/components/tile.tsx`, `src/features/home/*item-row*`), `src/api/queries.ts` (prefetch timer).

- [ ] On TV, the focus ring and scale are driven only by Reanimated shared values (ring opacity + scale on the UI thread). A focus change must not cause a React re-render of the tile unless the tile's children actually read the focused flag; find those readers and keep only them on state.
- [ ] Billboard: tile focus writes nothing to the billboard store until focus has rested 500 ms on that tile (new constant, replaces the store-write-then-350 ms flow). The item fetch and the backdrop change happen only after that. The 300 ms per-tile prefetch timer becomes part of the same settle (one timer, not two).
- [ ] Give each tile a stable `onFocusItem` (no new arrow per tile per render) so `memo` holds.
- [ ] Unit-test the settle logic as a pure helper (fast moves → one update for the last tile; rest → update).
- [ ] Commit: `TV: do no extra work while focus moves`.

### Task 2: Mount only visible tiles on Home

**Files:** `src/app/(tabs)/(home)/index.tsx`, `src/features/tv/shelf.tsx`, `src/features/tv/scroll.ts` if needed.

- [ ] Home on TV: rows below the visible area mount lazily (a vertical virtualized list of rows, or mount-on-approach), keeping the current "focused row slides up under the billboard" scroll.
- [ ] Each TV shelf: a horizontal virtualized list (FlashList or FlatList with `getItemLayout`, fixed tile step) with a small window (about one screen each side). Keep left-aligned focus scrolling with the existing native glide (300 ms, `tvDrivenScroll`).
- [ ] Focus memory per row must survive virtualization: keep the last focused index per row and, when focus enters the row, send it to that index (scroll there first if it is not mounted). Use the existing `TvFocusGuide`/`TVFocusGuideView` and focus helpers in `src/features/tv/focus.tsx`.
- [ ] Measure on the Android TV emulator (see AGENTS.md section 6 and the emulator notes the controller gives you): app PSS on Home before and after, and hold-Right behaviour. Put the numbers in the report.
- [ ] Commit: `TV: mount only the Home tiles near the screen`.

### Task 3: Lighter shell and player

**Files:** `src/features/tv/side-menu.tsx`, `src/lib/stack-options.ts`, `src/app/_layout.tsx`, `src/features/player/player-screen.tsx`, `src/features/player/scrubber.tsx`.

- [ ] Side menu: the open panel moves by `transform` (translateX) and opacity over the page instead of animating `width`; the page does not relayout during the animation. Drop the full-screen gradient scrim on TV (a static dim behind the panel is fine). Keep 240 ms or shorter.
- [ ] TV screen changes: native-stack `animation: 'none'` for pushes on TV and for the player route on TV. Phones unchanged.
- [ ] Player controls on TV: show and hide instantly (no fade), auto-hide after 3000 ms. Phones keep the fade and 3000 ms.
- [ ] All platforms: `PlayerScreen` must not re-render on every position tick. Move the `position` subscription down into the components that show it (seek bar, time labels, peek bar, skip buttons). Behaviour stays the same.
- [ ] Commit per item group (menu; transitions + controls; player re-render).

### Task 4: SmartTube focus look and D-pad repeat

**Files:** the TV tile caption code (from Task 1), `docs/design/theme.ts` + `src/theme/theme.ts` if a token is needed, `modules/zoggyfin-native/android/.../DpadRepeatThrottle.kt`.

- [ ] TV tiles with a caption under the image: when focused, the caption strip turns to a light surface with dark text instantly (no animation), like SmartTube; unfocused captions stay as now. Keep the 1.1x zoom; remove the white ring for these tiles only if the strip makes it redundant (your call, state it in the report). Use theme tokens.
- [ ] D-pad repeat: lower the native throttle from 140 ms to 100 ms (native; ships in the next TV build). Old binaries keep 140 ms.
