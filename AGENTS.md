# AGENTS.md

Guidelines for coding agents (and people) who change Zoggyfin.
Read this file before you change code. The skills in `.claude/skills/` give step-by-step procedures:
`verify-change`, `run-simulator`, `ship-update` and `add-item-action`. They are plain Markdown, so any agent can read them.

## 1. The project

Zoggyfin is an open-source client for [Jellyfin](https://jellyfin.org) media servers. License: MPL-2.0.
The goal is a client that is fast, stable and clear.

| Target | How it is built | State |
|---|---|---|
| iPhone, iPad | Expo dev client / EAS build | Beta (TestFlight) |
| Android phone and tablet | Expo / EAS build | Not released yet |
| Android TV, Fire TV (Apple TV in config) | Same app with `EXPO_TV=1` (react-native-tvos) | In progress, EAS profile `tv` |
| Web | `expo export --platform web`, static site | Self-hosted |
| macOS (Apple silicon) | Tauri 2 app in `desktop/` around the web build, libmpv for video | Signed DMG, own updater |

The rule from CONTRIBUTING.md: **every feature works on every platform**, or the app shows a clear message where it cannot.
`src/platform/tv.ts` (`features`) says what each platform has. TV has no downloads, no watch together and no extension panels. The web has no downloads, but the Mac app has them.

### Stack

- Expo SDK 58, Expo Router (typed routes), React 19.3 with the React Compiler on (`app.json` `experiments`).
- `react-native` is an alias for `react-native-tvos@0.88`. The new architecture (Fabric) is on.
- Data: `@jellyfin/sdk` + axios, TanStack Query (persisted per account), Zustand stores, MMKV (`react-native-mmkv`), `expo-secure-store` for tokens.
- Video: `expo-video` (iOS, Android), an HTML `<video>` element with `hls.js` (web), libmpv (Mac app).
- Audio: `expo-audio` (`AudioPlaylist`).
- Downloads: `@kesha-antonov/react-native-background-downloader` (iOS, Android), Rust in the Mac app.
- Watch together crypto: `@noble/*` 2.x, Apple CryptoKit on iOS.
- Desktop: Tauri 2, Rust, a Swift bridge, libmpv.
- Tests: Jest 30 with the `jest-expo` preset. TypeScript 6 with `strict`. ESLint 9 with `eslint-config-expo`.

### Commands

Use pnpm (version 10), not npm or yarn. Node 22 or later.

| Command | What it does |
|---|---|

| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm lint` | `expo lint` (`no-explicit-any` is an error) |
| `pnpm test` | All Jest tests |
| `pnpm jest src/downloads` | Jest tests under one path (any path or file name pattern) |
| `pnpm start` | Metro for an installed development build (`expo start --dev-client`) |

| `pnpm expo run:android` | Builds and runs the Android dev client |
| `pnpm expo start --web` | The web app in a browser. Add `?tv=1` to the URL for the TV layout preview |
| `pnpm expo start --web --port 8082` then `pnpm desktop:dev` | The Mac app in development (needs `brew install mpv` and Rust) |
| `pnpm desktop:build` | An unsigned Mac app for testing |
| `pnpm test:crypto-swift` | Checks the Swift rendezvous crypto against the shared test vectors (macOS) |
| `pnpm test:ts-bridge-swift` | Tests the Swift MPEG-TS segmenter and playlist builder of the TS bridge (macOS; with ffmpeg it also checks real streams with ffprobe) |
| `pnpm bench:together`, `pnpm stress:controls` | Watch-together benchmarks (see `docs/perf/together-bench.md`) |

`desktop:release`, `desktop:publish`, `desktop:version` and `site:deploy` are for the maintainer. They need keys that are not in the repository.

For `desktop/` changes also run, in `desktop/src-tauri`: `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`.
CI (`.github/workflows/ci.yml`) runs typecheck, lint and `pnpm test --ci`, and the Rust checks when `desktop/` changes.

`ios/` and `android/` are generated by prebuild (Expo CNG). They are not in git. Never edit them by hand: change `app.json`, a config plugin, `modules/` or `patches/` instead.

To try the app, use the public demo server `https://demo.jellyfin.org/stable`, user `demo`, no password.

### 2.1 Routes (`src/app/`)

- `_layout.tsx` is the root. It mounts the persisted query client (one cache per account), the theme provider, the root hosts (`ToastHost`, `RefreshSpinnerHost`, `UpdateCardHost`, `AddToPlaylistHost`, `ExtensionsHost`) and starts the offline services.
- `(tabs)/` holds the tab stacks: `(home)`, `(library)`, `(music)`, `(search)`, `(saved)` (Downloads). The shared detail routes are in `(home,library,music,search,saved)/` (`item/[id]`, `library/[id]`, `music/[id]`, `genre/[id]`), so a detail page stays in the tab that opened it (`src/lib/navigation.ts`).
- On TV, `(tabs)/_layout.tsx` renders a side menu instead of the tab bar (`src/features/tv/`).
- Modal and full-screen routes: `player.tsx` (video), `now-playing.tsx` (music), `join.tsx`, `share.tsx`, `extension-*.tsx`, `accept-invite.tsx`.
- `sign-in/`, `add-account/` and `offline/` work with no session. `+native-intent.tsx` maps incoming links.

### 2.2 API and data (`src/api/`)

- `jellyfin.ts` is the only wrapper over `@jellyfin/sdk`. Screens never call the SDK directly.
- `query-keys.ts`: every key starts with the session scope `['jf', serverId, userId]`. Two accounts never share cache. Invalidate with `queryKeys.all(scope)` or a narrower key.
- `queries.ts`: hooks that pair a key with a `jellyfin.ts` function. Screens use these hooks and nothing lower.
- `query-client.ts`: one persister per account (MMKV `zoggyfin-query-cache`), so a cold start shows the last content at once.
- `use-api.ts`: `useApi()` gives `{ api, userId, scope }` inside the signed-in layout.
- `auth-header.ts`: every request carries the `Authorization` header. URLs that cannot carry a header (images, streams) use `ApiKey=`.
- `item-seed.ts`: a tile passes what it knows to the item page, so the page renders before the full item loads.

### 2.3 Accounts and servers (`src/auth/`, `src/servers/`, `src/lib/online.ts`)

- `auth/accounts.ts` is pure data: servers, users, addresses. `session-store.ts` stores it; tokens go to the secure store, never into this data.
- `servers/addresses.ts` (pure) and `connection.ts` probe all addresses of a server in parallel and pick the first one in the user's order that answers with the same server Id. The mode (Automatic, Internal, External) and the Wi-Fi rule (`wifi-rule.ts`) apply.
- `lib/online.ts` is reachability: checks at start, on foreground, on a network change and after a failed request.
- `servers/discovery/` finds servers on the LAN: a UDP broadcast (`modules/zoggyfin-discovery` on native, Rust in the Mac app) plus an HTTP subnet scan. None on the web.

### 2.4 Video playback (`src/player/`)

Data flow for a play request:

```
Screen → usePlayer().play(request)                      player/index.ts
  → playRouter.route()   (a together session may take the request)   play-router.ts
  → playHere(): audio items → audio/session.ts, else videoSession()
videoSession().play()                                   session.ts
  → completed download on the device?  → playLocal(): file URI, progress → outboxOnly()
  → else resolvePlayable → getItem → getPlaybackInfo(device profile)  device-profile.ts
  → planStream(): URL, play method, tracks              stream.ts (pure)
  → engine.load(source)                                 getEngine()
       engine.native.tsx   expo-video (iOS AVPlayer, Android ExoPlayer)
       engine.tsx          web: <video> + hls.js, or MpvEngine in the Mac app (engine-mpv.ts)
  → ProgressReporter (start, every 10 s, pause/seek/stop)  progress-reporter.ts
       → withOutbox(transport): offline → outbox, sent later  outbox-transport.ts
  → setPlayerState()                                     store.ts → player screen, mini player
```

- `engine-types.ts` is the seam. The session drives the engine. Screens never touch an engine.
- `device-profile.ts` tells the server what the device plays directly. Capabilities come from `capabilities.native.ts` (decoders) or `capabilities.ts` (browser probe, or libmpv in the Mac app).
- Pure helpers with tests: `stream.ts`, `segments.ts` (Skip Intro, next-up), `timeline.ts` (trickplay, chapters), `tv-keys.ts` (TV remote keys), `position-line.ts` (smooths libmpv positions), `vtt.ts`.
- `control-gate.ts` sends play, pause and seek to a together session while one runs.
- The player UI is in `src/features/player/` (`player-screen.tsx`, `scrubber.tsx`, `mini-player.tsx`, `subtitle-overlay.tsx`, `global-keys.tsx`).
- Audio: `audio/session.ts` owns the queue (`queue.ts`, pure), drives `audio/engine.ts` (one `expo-audio` playlist for the app's life), reports progress, keeps long-form positions (`positions.ts`, `long-form.ts`) and runs the sleep timer. The music player UI is in `src/features/music-player/`.

### 2.5 Downloads (`src/downloads/`)

```
Action "Download" → downloads.download(item)            index.ts (the only import for screens)
  → plan.ts (pure): original file or a server transcode, and the URL
  → manager.ts: queue, at most 2 at a time, extras (images, subtitles, lyrics, item.json)
       → state-machine.ts (pure): queued → downloading → paused/completed/failed/cancelled
       → engine: engine.native.ts → native-engine.ts (logic, deps injected)
                   → background downloader (patched); resume.ts: Range request + join
                 desktop.ts → Rust (desktop/src-tauri/src/downloads.rs)
                 engine.ts → web and TV: none
  → store.ts: records in MMKV, versioned (types.ts, migrate.ts)
Play → session.ts finds the completed record (local.ts) → plays the file → outbox when offline
```

- Files are under `<documents>/downloads/<itemId>/`, collections under `downloads/collections/<id>/`.
- `outbox.ts` (pure rules) + `outbox-store.ts`: one entry per item, keyed by server Id and user Id. `flushOutbox()` sends each entry only to its own server (`features/offline/bootstrap.ts` runs it when a server answers again).
- A download from another saved server ("foreign") makes no server calls; its progress goes to the outbox.
- `relink.ts` and `move-server.ts` move downloads to a reinstalled server with a new Id.
- `lists.ts` builds the Downloads tab and the offline search.

### 2.6 Watch together (`src/together/`)

- `hub.ts`: one "session" idea over two transports. `store.ts` is the UI state.
- Internet mode: `syncplay.ts` (Jellyfin SyncPlay), pure helpers in `syncplay-logic.ts`.
- Nearby mode: `nearby.ts` (controller), `room.ts` (host: the clock and the authority), `follower.ts` (guest), `protocol.ts` (versioned JSON wire messages), `machine.ts` (state machine), `recovery.ts` (drops), `join-gate.ts`, `join-code.ts`, `budget.ts` (host upload).
- Sync: `clock.ts` (NTP-style offset), `drift.ts`, `anchor-follower.ts`.
- Transport: `link.ts` (handshake) over `link-native-types.ts`. Implementations: `modules/zoggyfin-native` (iOS Network.framework + BLE, Android NSD + BLE + local-only hotspot) and `link-desktop.ts` (the same Swift code in the Mac app).
- `rendezvous.ts` + `rendezvous-crypto.ts`: the BLE rendezvous (X25519, cipher primitives in `rendezvous-cipher.ts` with @noble, `rendezvous-cipher.ios.ts` with CryptoKit). Both must give the same bytes as `__tests__/rendezvous-vectors.json`.
- Player bindings: `player-binding.ts`, `player-port.ts`, `audio-binding.ts`.
- Test helpers: `test-utils/fake-link.ts` (in-memory network) and `test-utils/sim.ts` (virtual clock).

### 2.7 Extensions and registries (`src/extensions/`, `src/registry/`)

- `registry/item-actions.ts`: `createRegistry()`, the `ItemAction` type and `actionsFor()`. An action whose `when` throws is hidden; it never breaks the sheet.
- `registry/home-sections.ts`: Home renders every registered section in `order`.
- Built-ins register through the same registries: `features/actions/builtin.ts` (orders in steps of 10) and `features/home/builtin-sections.tsx`.
- `features/actions/use-item-actions.ts` supplies the `AppActionApi` (play, favourite, download, delete and so on) to the sheet.
- `extensions/runtime.ts` turns installed manifests (`schema.ts`) into item actions (`ext.<id>.…`), Home rows (order 45+) and share targets. Extensions are data only: no extension code runs in the app. Requests go only to the manifest's origin (`http.ts`, `match.ts`). See `docs/extensions.md`.

### 2.7a Live TV (`src/iptv/`)

- Pure, tested parsers: `m3u.ts` and `xmltv.ts` take text in chunks; `xtream.ts` reads the Xtream JSON. `text-stream.ts` decodes UTF-8 and gzip (`fflate`) in chunks and yields to the event loop, so a list of 100k channels never blocks the UI.
- `manager.ts` loads, refreshes and saves providers. Provider records are in MMKV per account (`iptv.providers.<serverId>.<userId>`); passwords and tokenised list URLs are only in the secure store (`secrets.ts`).
- Channel lists and the guide window are files (`files.native.ts`, `files.ts`). Fetches go through `transport.native.ts` (a download to a cache file), the Rust command `iptv_fetch` in the Mac app, or `fetch` on the web (CORS).
- `stream-url.ts` picks the stream form per platform: HLS on iOS and the web, `.ts` on Android and the Mac app. It tries the Xtream HLS form of an M3U `.ts` URL before it gives up on iOS.
- Play: `iptv.playRequest()` builds a `LivePlayRequest` for `usePlayer().playLive()`. The session sends no Jellyfin progress and has no duration. `player/index.ts` refuses a live request while a together session runs.
- Saved shapes are versioned (`migrate.ts`). Error texts never contain a URL (`errors.ts`).
- Films and series (phase 3, `vod-*.ts`): `xtream-vod.ts` parses `get_vod_*` and `get_series*` (pure); `m3u-vod.ts` moves the film and episode entries of an M3U list out of the channel list (`manager.ts` `showChannels`); `vod-manager.ts` loads categories, a category when it opens, all titles for a search, and details, each cached in `iptv/<providerId>/vod/` (memory only on the plain web) and loaded again when a day old; `vod-hooks.ts` is the screens' surface (re-exported by `index.ts`).
- `vod-stream.ts` picks the film or episode stream: the file as it is on Android and the Mac app; MP4, M4V, MOV and HLS on iOS and Apple TV, else the panel's `.m3u8` form, else a message; browsers also try MKV as a file.
- Play: `filmRequest()` / `episodeRequest()` build a `VodPlayRequest` for `usePlayer().playVod()`. The session saves the position through the source (`vod-lists.ts`, MMKV `iptv.vod.<providerId>`, versioned in `vod-migrate.ts`), every 10 s, on pause and on stop; never to Jellyfin. The next episode is the next-up item; Next marks the episode left as watched.

### 2.10 Platform files

Metro picks a platform file by suffix. The pattern in this repo:

- `x.ts` is the web (and default) version; `x.native.ts` is iOS and Android. Example: `storage/kv.ts` (localStorage) and `kv.native.ts` (MMKV).
- `x.ios.ts` and `x.web.tsx` exist where one platform differs (`rendezvous-cipher.ios.ts`, `icon.web.tsx`, `airplay-button.ios.tsx`).
- A shared `x-types.ts` file holds the interface that both versions implement (`engine-types.ts`, `files-types.ts`, `kv-types.ts`).
- The Mac app runs the web build. Detect it with `src/platform/desktop.ts`, not with `Platform.OS`.
- TV runs the native files. Detect it with `isTV` / `isNativeTV` / `features` from `src/platform/tv.ts`.

## 3. Code conventions

Follow the code around you. These rules come from the code base and CONTRIBUTING.md.

- **Comments explain why.** Each module starts with a short doc comment that says what it is for and the rules it keeps. Do not describe what the code says.
- **Pure core, thin I/O.** Put rules in pure modules with no React and no native imports, and test them (`state-machine.ts`, `stream.ts`, `queue.ts`, `addresses.ts`). Pass I/O in as parameters: `native-engine.ts` takes the downloader and the file operations, `ProgressReporter` takes a transport and a timer. Mark such files with "Pure, so it is unit-tested" in the doc comment, like the existing ones.
- **State machines return the same object** when an event does not apply, so a caller can test `next === prev` (`downloads/state-machine.ts`, `together/machine.ts`, `platform/updates/machine.ts`).
- **One import surface per area.** Screens use `@/player` (`usePlayer`), `@/downloads` (hooks and `downloads`), `@/api/queries`. They never import an engine, the native downloader or the SDK.
- **Saved data is versioned.** Download records have a schema version and migrations (`migrate.ts`). A migration never throws. Never change a stored shape without a migration.
- **Optional native modules.** Load a local native module with `requireOptionalNativeModule` and handle `null` (see section 5).
- **Design system.** Use `useTheme()` (`c` colours), `useStyles` / `createStyles`, `font()`, `sizes` and the layout helpers from `@/theme`. Never put a raw colour or size in a style. Icons: use `<Icon>` with an SF Symbol name from `components/icon-names.ts` (Android maps it to Material Symbols, the web to Lucide). Pressables: `components/touchable.tsx` (press feedback and TV focus). Confirm a destructive action with `lib/confirm.ts`. Show feedback with `lib/toast.ts` (one toast at a time).
- **Design tokens** live in `docs/design/theme.ts`. `src/theme/theme.ts` is a copy: edit the docs file first, then copy it.
- **Layout follows the window**, not the device: `useLayout()`, `useWindowDimensions`. iPad and the Mac app have wide layouts. TV has 10-foot sizes (`theme/layout.ts`).
- **Errors**: turn errors into a message with `describeError()` / `errorText()` from `api/errors.ts`. Never log tokens, one-time passwords or invite payloads.
- **Web must work on plain http** (self-hosted LAN): no hard dependency on `crypto.randomUUID`, `crypto.subtle` or other secure-context APIs (see `lib/id.ts`).
- **Naming**: kebab-case file names, `useX` hooks, `xStore` / `useXStore` for Zustand stores, registry ids `builtin.<name>` and `ext.<extensionId>.<name>`.
- **TypeScript**: `strict`, no `any`. Fix every lint warning that your change adds.
- **User-facing text**: plain English, short sentences, active voice. The UI uses British spelling ("favourites").
- **Dependencies**: do not add one without a reason. A native dependency forces a native build (section 5).
- **Tests** live in `__tests__/` next to the code. Fixtures are in `test-utils/` folders. Add or update a test when you fix a bug or add logic.

## 5. Native build or over-the-air update

Expo apps ship JavaScript in two ways: a native build (store or TestFlight), or an over-the-air (OTA) update with `expo-updates`.
The `ship-update` skill has the full procedure.

**A change needs a native build when it touches:**

- `modules/**` (Swift, Kotlin, podspecs, `expo-module.config.json`).
- `patches/**` that patch native code. Both current patches do: `expo-video` (`NowPlayingManager.swift`) and the background downloader (Android Kotlin).
- A dependency with native code: added, removed or upgraded (`expo-*`, `react-native-*`, `@kesha-antonov/*`, Nitro modules).
- `app.json` native config: `ios`, `android`, `plugins`, permissions, entitlements, `infoPlist`, icons, splash, `scheme`.
- The Expo SDK or `react-native-tvos` version.

**A JS-only change ships as an OTA update:** code in `src/`, assets that Metro bundles, JS-only dependencies (for example `zod`, `zustand`).
The Mac app and the web are different: the Mac app embeds the web build (`frontendDist: ../../dist`), so a JS change reaches it only with a desktop release. The web needs a new static export.

**Rules:**

- `runtimeVersion` uses the `appVersion` policy. All binaries with the same `version` in `app.json` get the same OTA updates. **Do not change `version` casually.** A new `version` cuts every installed binary off from new updates until people install the new build. Only the maintainer decides on a version change. TV sideload releases keep the same `version`: the Android TV updater compares `versionCode` only.
- Because old binaries get new JS, **new JS must not need a native module that older binaries lack.** Load native modules with `requireOptionalNativeModule` (from `expo`) and give a safe fallback when it returns `null`. Examples: `src/native/zoggyfin-native.native.ts`, `src/together/nearby-native.native.ts`, `src/servers/discovery/backend.native.ts`, `src/invite/clipboard.ts`. Never add a top-level `import` of a new native package in code that an OTA update ships.
- A JS workaround for a native bug stays until every supported binary has the native fix. Example: `engine.native.tsx` always passes `artist` and `artwork` to expo-video (see section 6), and the patch fixes the native side for new builds.
- Patches apply through `pnpm.patchedDependencies` in `pnpm-workspace.yaml` during `pnpm install`. To change one: `pnpm patch <pkg>@<version>`, edit, then `pnpm patch-commit <dir>`. A patch file name pins the exact version: upgrade the package and the patch together.
- **A native patch of an Expo module works only if that module builds from source.** On iOS, Expo uses precompiled xcframeworks for most `expo-*` modules (`EXPO_USE_PRECOMPILED_MODULES`). A precompiled module ignores the patched Swift in `node_modules`. Put each patched Expo module in the `expo.autolinking.ios.buildFromSource` list in `package.json` (now: `expo-video`). After `pnpm expo prebuild --clean --platform ios`, the module must not appear in the "Precompiled modules" list of the pod install output.
- **Verify a native patch in the build log.** Build for iOS and search the log for the patched file, for example `grep NowPlayingManager.swift <build-log>`. No match means the patch is not in the binary.
- EAS profiles (`eas.json`): `development` (dev client), `preview`, `production`, `tv` (`EXPO_TV=1`, the sideloaded Android TV APK with the self-updater, on its own `tv` channel) and `tv-play` (the TV app bundle for Google Play, no self-updater, on `production` with the other Google Play builds). An OTA update to `production` does not reach TV builds: publish to `tv` too (`--platform android`), and check TV. TV APKs built before this change are on `production`.

## 6. Gotchas learned the hard way

- **Run Jest from the repository root.** Agent worktrees live in `.claude/worktrees/<name>/` and hold full copies of `src/`. Jest must not run those copies: the Jest config ignores `<rootDir>/.claude/`. Do not run tests from a parent folder, and do not remove that ignore pattern.
- **Do not start Metro with `CI=1`.** `CI=1` turns off reloads and Fast Refresh, so your changes never reach the app on the simulator. Start Metro with a plain `pnpm start`.
- **iOS 26 large titles and pull to refresh.** On iOS 26 the `UIRefreshControl` spinner disappears after a pull while the refresh still runs. The app hides the native spinner and draws its own from the root (`src/components/refresh-spinner.tsx`, `RefreshSpinnerHost` in `src/app/_layout.tsx`). A new large-title screen with pull to refresh must use `usePullRefresh()` and pass `tintColor={refreshTint(c.text2)}` to its `RefreshControl` and call `useRefreshSpinner(pull.refreshing)`. See `src/components/item-grid.tsx`. The app has no large titles now, but every page with pull to refresh keeps these rules, so the spinner looks the same everywhere. A headerless tab root page passes `useRefreshSpinner(pull.refreshing, true)` (ItemGrid: `headerless`), so the spinner sits under the status bar.
- **Tab root pages have no title.** They use `useRootScreenOptions()` from `src/lib/stack-options.ts`: no header (the screen pads its top by the status bar), or `{ bar: true }` for a slim header with buttons or a native search field. Do not add a large title back to a tab's first page. A page that is a tab root in one stack and a pushed page in another (Live TV) uses the root options only in its own tab.
- **expo-video and Now Playing on iOS.** With no artist or artwork from the app, expo-video put the file's own `AVMetadataItem` (embedded cover art) into the Now Playing info, and MediaPlayer aborted the app. `engine.native.tsx` always passes `artist` and `artwork` (`NO_ARTWORK` when there is none). `patches/expo-video@58.0.13.patch` fixes the native side. Keep both.
- **The expo-video patch was never in build 12.** Expo used its precompiled ExpoVideo xcframework, so the patched `NowPlayingManager.swift` did not compile. Only the JS workaround protected those builds. `package.json` now builds expo-video from source (`buildFromSource`). Do not remove that entry while the patch exists, and check the build log for `NowPlayingManager.swift` after a native build.
- **Typing "d" on the iOS simulator** with the hardware keyboard opens the dev menu. Type text only into a focused text field.
- **Worktrees and tools.** Jest (`package.json`), `tsc` (`tsconfig.json` `exclude`) and ESLint (`eslint.config.js` `ignores`) all ignore `.claude/`. Keep these entries when you change the configs.
- **`ios/` and `android/` are generated.** Run `pnpm expo prebuild --clean` after a native config change. Switching between a phone build and a TV build (`EXPO_TV=1`) also needs a clean prebuild.
- **Development helpers.** Settings, Development has "Simulate no server" (offline mode) and "Admin fixture data". Development builds write a together sync log (`together/sync-log.native.ts`).
- **The web runs on plain http.** Test web changes on `http://`, not only on `https://localhost`.

## 7. Git and workflow

- Make small, focused commits. One commit does one thing.
- Commit message: one short imperative line, capital letter, no period, no `feat:` prefix, under about 72 characters. An area prefix is fine: `Player: …`, `TV: …`, `Android: …`, `Together: …`. Then a blank line and the reason. Look at `git log` for examples.
- Work on a branch from `main`. Put agent worktrees only in `.claude/worktrees/<name>` (it is in `.gitignore`).
- This repository is public. Never commit secrets, keys, tokens, `.env` files, signing files, private server addresses, host names, local paths or personal data. Use the public demo server for screenshots and test data. Use generic names ("Jane Doe") in tests.
- Commits use the project identity `zog-tech`. Check `git config user.name` before you commit.
- Update `README.md`, `docs/` and `CHANGELOG.md` when a change alters what the app does. Mac app release notes go in `desktop/CHANGELOG.md`.
- Do not push, release, publish an OTA update or deploy the site unless the maintainer asks.
- Contact for the project: admin@zog-tech.com. Security reports: see `SECURITY.md`.
